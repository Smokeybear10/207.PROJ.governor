# TokenGovernor — Hackathon Strategy

## Judging criteria (from organizers)

1. Technical complexity
2. Pitch
3. How good the idea is
4. Investable
5. Fits the track

Team read: technical complexity is covered (deterministic enforcement kernel,
201 tests). Pitch, idea clarity, investability, and track fit are the gaps.
Everything built between now and 3 PM should serve those four.

## Track fit

- **Save Time. Save Money.** — primary. TokenGovernor is literally a money
  governor for AI spend. Every demo sentence should tie back to a dollar
  amount.
- **Best Use of OpenAI API/Codex** — submit here too. Requires the live
  Responses API path (Aryan) to be real: at least one governed run with
  measured provider usage beats any amount of synthetic polish for this track.
- Audience Favorite — free to enter; the station demo is the vote.

## Demo constraints that shape the build

- Science-fair format: people walk past a station. The screen has to explain
  itself in under 15 seconds with nobody driving.
- Finalist window is 5 minutes: one governed run end to end plus the
  comparison screen, no setup time.
- Hard 3 PM freeze. Anything not demoable by 2:30 gets cut.

## The 15-second story

An AI agent gets a budget. A hard cap kills it mid-job; money spent, nothing
delivered. TokenGovernor reserves cost before every call, intervenes when the
job drifts, and lands the finished review under the ceiling. Same quality
gate, fewer dollars.

## Honesty line (Azdeen)

Synthetic fixtures are labeled on screen. Say "deterministic scripted
mechanism" for the walkthrough and "real measured usage" only for live runs.
The claims guide in docs/TOKEN_GOVERNOR.md section 31 has safe wording.
